# shotpvp —— 终端双人反弹坦克竞技场

本地双终端联机竞技乱斗：一个权威服务端 + 两个 UDP 客户端。包含 3×3 Unicode
坦克、反弹自伤子弹、可破坏砖墙，以及缩小、三连发、一次性护盾三种随机道具。
每局倒计时 3 秒，先到 5 分获胜；结算后双方按开火键重开。

移动和瞄准支持八方向：WASD 可组合斜向（WA/WD/SA/SD），方向键保持四向。
三连发会沿当前方向发射三条平行弹道；对角子弹按撞击面的分量进行反弹。

## 无服务器直连（实验性）

- 创建房间：`python client.py --host`，把显示的 10 分钟临时连接码发给对方。
- 加入房间：`python client.py --join-code <连接码>`，程序会认证并选择 RTT 最低的候选路径。
- 手动直连：`python client.py --connect 192.168.1.20:47000`。
- 原本地模式保持不变：先运行 `python server.py`，再运行两个 `python client.py`。

连接码包含临时 IP/端口，应只发给本局玩家。公网房间不会发布回环或 APIPA（169.254.x.x）地址；公网直连仍受运营商 NAT 限制：对称 NAT
可能无法打洞，当前没有 TURN/VPS 中继保证。失败时允许 Python 通过 Windows 防火墙，确认路由器
UPnP 已开启，或尝试 IPv6/手动端口映射。真实跨运营商测试和防火墙弹窗需在 Windows 主机手测。

当前一次连接只使用一个 socket 地址族：连接码同时包含 IPv4/IPv6 时优先尝试 IPv4，尚未实现双栈同时竞速；同地址族内仍按实测 RTT 选择路径。

## 运行

需要 Windows + Python 3.8+（无第三方依赖）。

**1. 启动服务端**（开一个终端窗口）

```
cd D:\vibe-coding\shotpvp
python server.py
```

看到 `等待 2 个客户端连接...` 即可。

**2. 启动两个客户端**（再开两个终端窗口，各跑一个）

```
cd D:\vibe-coding\shotpvp
python client.py
```

两边都看到 `已连接，你的 player_id = ...` 后，双方就绪即开始对战。

## 操作

- 方向键 / WASD：按住持续移动
- 空格 或 回车：开火
- ESC：退出

## 当前玩法

- 64×30 对称竞技场，普通坦克为带外伸炮管的 3×3 Unicode 图形。
- 子弹撞边界、钢墙和砖墙会反弹；砖墙被命中一次后破坏。
- 子弹最多反弹 5 次，可以伤害发射者；护盾可抵消一次伤害。
- 逻辑层已支持临时缩小和一次性三向射击效果。

## 架构

- `protocol.py` —— UDP 二进制消息协议（JOIN / JOIN_ACK / INPUT / STATE / LEAVE）
- `game.py` —— 纯游戏逻辑（地图、坦克、子弹、碰撞），服务端客户端共用
- `input_win.py` —— Windows Console API 真实按键事件采集
- `renderer.py` —— ANSI 差分渲染（只重绘变化的格子，避免闪烁）
- `server.py` —— 权威服务端，30Hz tick 推进世界并广播状态
- `client.py` —— 客户端：输入采集 + 本地预测 + 状态收包 + 渲染

## 同步模型

状态同步：服务端权威，30Hz 广播世界快照；客户端按键立即发 INPUT 包，同时对本地坦克做预测移动（不等服务器回包）。原型阶段远端坦克直接使用最新快照，未做插值。

## 已知限制

- 仅 Windows（输入层依赖 Win32 Console API）
- 远端坦克使用约 100ms 快照缓冲插值
- HUD 显示真实 RTT，3 秒收不到状态时提示连接中断
- 无重连/掉线检测
- 地图固定，无随机生成
